//👉Internet:- 
We get internet in India through undersea fiber optic cables that land on our coasts.These cables are laid across 
the ocean floor and plug into heavily guarded buildings on our beaches called Cable Landing Stations.

//1. Where Does the Internet Come From?
The cables connecting India travel via two main underwater highways:

From the West: Cables travel from Europe (France, UK, Germany), pass through the Red Sea and the Middle East (Oman, UAE), 
and land on India's west coast.

From the East: Cables travel from Southeast Asia (Singapore, Hong Kong, Japan) and land on India's east coast.

//2. How it Reaches Your Device (The 4-Step Chain)

1. The Ocean Floor: Data travels as fast pulses of light through the glass fibers inside these massive undersea cables.

2. The Beach (Landing Hubs): The cables exit the ocean at major coastal cities—primarily Mumbai (handling 70% of traffic) 
and Chennai.
 
3. Under the Streets: Telecom companies (like Jio, Airtel, and Tata) pick up the data from the beach and send
it across the country through a massive web of underground fiber cables buried beneath city roads.

4. Through the Air: The underground cables connect directly to local cell towers or your home Wi-Fi router. 
The tower/router converts the light into wireless radio waves, which beam directly into your phone.

//👉express.js-> Express.js is a lightweight toolkit that makes it much easier to build web servers and APIs using JavaScript.
It runs inside Node.js (the environment that lets JavaScript run on a computer instead of just inside a web browser)
-> express.js is a framework for node.js

If Node.js is the car engine, Express.js is the steering wheel, dashboard, and pedals that make driving the car simple.

Technically, you can build a web server using only raw Node.js, but it requires writing a lot of complex, repetitive code 
just to handle basic tasks. Express.js provides pre-written shortcuts so you don't have to reinvent the wheel

It mainly simplifies three things:
//1. Routing: Directing users to the right place. For example, telling the server: "If someone visits ://mywebsite.com, 
show them the contact page". 

//2. Handling Requests & Responses: Easily reading information sent by a user (like a login password) and sending back the 
right response (like logging them in or showing an error). 

//3. Middleware: Plug-and-play features. These are tiny helper programs you can drop into your server to handle complex tasks
automatically, like checking if a user is logged in, or logging data for security.
Before your server sends back a webpage or data, the request has to pass through these helpers first. They check, change, or filter the request.


💻Developers use middleware to handle repetitive tasks automatically. Here are the most common uses:

//1. Authentication (The Bouncer): It checks if a user is logged in. If they are, it lets them see their profile. 
If not, it redirects them to the login page.

//2. Logging (The Tracker): It takes a note of every single person who visits your site 
(e.g., "User at 10:15 PM visited the shop page") and saves it to a file.

//3. Data Parsing (The Translator): If a user fills out a form, the data arrives at the server as a giant, messy lump 
of text. Middleware converts that text into a clean JavaScript object that your code can easily read.

### 🌐 For Web Browsing & Apps
* HTTP – Fetches standard webpages and data.
* HTTPS – The secure, encrypted version of HTTP.
* WebSockets – (two way communication) Keeps a live, two-way connection open for real-time apps like live chats, stock tickers, and online games.

### 📧 For Email
* SMTP – Sends your emails out to the internet.
* IMAP – Retrieves and syncs emails so you can read them on multiple devices.
* POP3 – An older protocol that downloads emails to a single device and deletes them from the server.

### 📁 For File Sharing
* FTP / SFTP – Moves files between computers (SFTP adds security).
* SMB – Allows computers on the same local network to share files and printers.

### ⚙️ For Internet Infrastructure & Automation
* DNS – The phonebook of the internet; translates domain names (like google.com) into IP addresses.
* DHCP – Automatically assigns an IP address to your device when you connect to Wi-Fi.
* SSH – Allows developers to securely log into and control remote servers via a terminal.

📋What is HTTP?
It is a set of rules that allows your web browser, phone, or computer to send messages back and forth with a website's server.

What are HTTP Methods?
When you send a message over the internet, you have to tell the server what you want it to do. HTTP Methods (also called verbs) 
are the action words in that message.

The most common ones are:
GET - Read -> Retrieves data from the server without modifying anything.
POST - Create -> Submits new data to the server to create a new resource.
PUT - Update -> Completely replaces an existing resource or creates it if it doesn't exist.
PATCH - Update -> Applies partial modifications to a resource. -> Only send the fields you want to change 
DELETE - Delete -> Permanently removes a specific resource from the server.

📋What is a REST API?
REST is just a highly organized set of style guidelines for building that API.

What are REST API Methods?
REST API methods are actually the exact same HTTP methods (GET, POST, PUT, DELETE), but they are strictly organized to
handle data in a predictable database loop called CRUD:

POST = Create (Add a new user)
GET = Read (View a user's profile)
PUT / PATCH = Update (Edit a profile)
DELETE = Delete (Remove a user)

👉The Relation Between HTTP and REST API Methods

HTTP provides the tools: It gives us the verbs (GET, POST, etc.). However, HTTP doesn't care how you use them. 
You could technically use a GET request to delete a file, even though it's bad practice.

REST provides the rules: REST is a design philosophy that forces you to use HTTP methods correctly and cleanly. 
In a REST API, you must use GET only to read, POST only to create, and URLs must always target "things" (like /users or /products).
